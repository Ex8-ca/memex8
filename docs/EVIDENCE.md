# Experimental explicit REST evidence

Status: first local M1 slice, opt-in; not a complete evidence rollout. Do not activate against production until backup/restore and erasure gates are complete.

## What works

With `[evidence] enabled = true` in the memex8 TOML configuration, an explicit REST memory creation can retain caller-pre-redacted source content and attribution. SQLite lives at `evidence.sqlite3` beside the configured `turbovec.index_path`; place that directory on the existing persistent data mount. It is not automatically persistent merely because evidence is enabled.

Request to authenticated `POST /api/v1/memories`:

```json
{
  "content": "Caller-redacted source text",
  "tags": ["project:example"],
  "idempotency_key": "stable-client-event",
  "evidence": {
    "speaker": "user",
    "origin": "explicit_rest",
    "pre_redacted": true,
    "session": "example-session"
  }
}
```

- Speaker is `user`, `assistant` or `tool`. Origin is currently only `explicit_rest`.
- Optional metadata: `agent`, `device`, `session`. Capture time is generated by the server; historical capture timestamps are not yet accepted.
- `pre_redacted=true` is a caller assertion, **not automatic secret detection**.
- Maximum source content: 65,536 UTF-8 bytes. Line endings normalize to LF. Evidence spans are UTF-8 byte offsets over that normalized stored text.
- The idempotency key reserves stable source/memory UUIDs transactionally. Reusing it with conflicting request content is rejected. After embedding failure the exact same request can retry without allocating a second pair of IDs.
- Evidence requests do not accept legacy `source` or `realm_hint` fields; use tags for organizational scope. Those tags are not per-client authorization.
- Read memory by ID to obtain `evidence_refs`, then authenticated `GET /api/v1/memories/{memory_id}/evidence/{source_id}`. The source is readable only with its exact extant memory linkage and matching tags/visibility.

SQLite and Qdrant are **not a single atomic transaction**. A prepared source can survive failed projection; the linked read endpoint does not expose unlinked prepared text. Pending text still exists on disk and needs the same retention protection as completed evidence.

Legacy create operations without `evidence` remain unchanged. Capture is disabled by default. No external URL/path is fetched by evidence lookup.

## Intentional refusal gates

Until safe lifecycle support exists:

- Evidence-linked memory edits and deletion are refused. Do not use this feature for information that must be erasable yet.
- Slumber is refused when evidence is enabled or its ledger has records.
- Unsupported logical backup/export/import/restore is refused rather than producing dangling references. Disabling capture does not bypass existing ledger/reference checks.
- A Qdrant copy without the matching SQLite ledger is not a complete evidence backup.

Use stopped-writer paired volume backup only, with SQLite inside the archived writable mount and no external writers. A production paired restore drill has **not** been completed.

## Not implemented

Provider/session/file ingestion attribution, automatic redaction, source revisions, historical timestamps, source erasure, recall receipts, evidence UI, logical paired transfer and reviewed slumber are not part of this slice. Do not assume explicit REST capture enables automatic chat capture with evidence.
